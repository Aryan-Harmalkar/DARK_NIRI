# Wallpaper Engine Integration Plan
**For Wayland/Niri Ecosystem & WebKitGTK 6.0 Engine**

## 1. Analysis of Current Infrastructure
- **Engine (`wallpaper-engine` / `wp-ipc`)**: A highly robust WebKitGTK 6.0 implementation operating as a persistent background Wayland surface. It handles IPC (`wallpaperctl`), window geometry, and exposes a JS API (`window.wallpaper`) for system telemetry (CPU, battery) and obscuration events (pausing rendering to save battery).
- **Template (`themes/html-wallpaper-template`)**: A well-structured starter for Three.js + Anime.js, implementing FPS throttling, WebGL context loss recovery, system bridge (battery aware downscaling), and critical resource cleanup.
- **The Problem (`generate_wallpaper.py`)**: The current One Piece wallpaper is statically generated by a Python script that injects a massive HTML string with inline CSS/JS and base64 images. This completely bypasses the modularity and 3D capabilities of the WebKitGTK environment and is hard to maintain.

## 2. Architectural Design & Modularity
To integrate "One Piece" and "Cyberpunk 3D" wallpapers cleanly, we must transition from static monolithic files to a modular component architecture.

### A. Shared Core Library (`themes/shared/`)
Extract the boilerplate from `html-wallpaper-template` into a reusable module.
- `themes/shared/lib/three.min.js`, `anime.min.js`
- `themes/shared/engine-core.js`: 
  - **Renderer Manager**: Three.js WebGL initialization, resize handlers, context loss/restore, and memory disposal.
  - **System Bridge**: Connects `window.wallpaper` for battery alerts (drops FPS/resolution) and obscured states (pauses `requestAnimationFrame`).
  - **Parallax Controller**: Manages dampening calculations for mouse movement.

### B. Theme Data Structure
Every 3D theme will follow a strict standard:
```text
themes/<theme-name>/
├── index.html        # Clean shell (includes shared libs and theme script)
├── theme.js          # Theme-specific Three.js/Anime.js logic
├── wallpaper.json    # Metadata for wallpaperctl (name, type, fps)
└── assets/           # Textures, models, JSON data
```

## 3. Implementation Steps

### Phase 1: Core Engine Refactoring
1. Create `themes/shared/` directory. Move `three.min.js` and `anime.min.js` here.
2. Abstract the WebGL boilerplate from `html-wallpaper-template/index.html` into `themes/shared/engine-core.js`.
3. Modify `engine-core.js` to expose hooks (`onInit`, `onRender`, `onDispose`) that individual themes can implement.

### Phase 2: One Piece 3D Integration (`themes/one-piece-3d/`)
1. **Deprecate `generate_wallpaper.py`**. Move the base64 images into standalone optimized `.webp` files in `themes/one-piece-3d/assets/`.
2. Extract the character metadata into `themes/one-piece-3d/assets/data.json`.
3. **HTML Overlay & UI**: Keep the UI overlay (stats, name, buttons) in `index.html` but stripped of logic. 
4. **`theme.js`**:
   - Initialize 3D particle system (e.g., cherry blossoms or water drops falling in the background).
   - Load character images onto 3D Planes (Three.js `MeshBasicMaterial` with alpha) to allow true depth and parallax based on mouse movement.
   - Use Anime.js to sequence the 3D plane transitions (slides/fades) and HTML DOM updates simultaneously when characters swap.

### Phase 3: Cyberpunk 3D Integration (`themes/cyberpunk-3d/`)
1. **Setup**: Create the theme directory and `wallpaper.json`.
2. **`theme.js`**:
   - Construct a neon grid floor using Three.js `GridHelper`.
   - Implement custom GLSL shaders (ShaderMaterial) for rain drops on the "camera lens" and glitch/chromatic aberration effects.
   - Tie the speed of the grid or the intensity of the glitch to system telemetry (e.g., if `window.wallpaper.telemetry.cpu > 70%`, intensify the glitch effect).
3. Ensure heavy post-processing effects are automatically disabled when `engine-core.js` detects battery saver mode.

### Phase 4: Integration with `wallpaperctl`
1. Ensure the new themes are discoverable via `wp-ipc list`.
2. Update `config.json` to support passing dynamic configuration to the themes via IPC (e.g., `wallpaperctl set-effect cyberpunk_glitch 0.8`), which the WebKitGTK engine will relay to `window.wallpaper.on('effect')`.

## 4. Performance Considerations
- **Memory Leaks**: The `engine-core.js` must strictly dispose of geometries, materials, and textures when switching themes. 
- **GPU Throttling**: Niri/Wayland obscured state *must* pause the render loop. If a window covers the screen, 3D rendering should halt.
- **Asset Loading**: Use `THREE.TextureLoader` asynchronously to prevent Wayland surface lockups during initial theme load.
