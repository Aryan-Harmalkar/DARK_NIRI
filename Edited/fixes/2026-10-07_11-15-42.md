# Session: Fix QuickShell Settings Reverting to Default on Reboot & Logout

**Date:** 2026-10-07 11:15:42
**Category:** fixes

## Modifications
- Added persistent disk state storage and startup restoration across all 4 QuickShell settings domains (Theme, Bar Style, Power Profile, and Wallpaper Engine).
- Updated `quickshell/powerprofile.sh` to write profile changes to `~/.config/niri/power_profile` and added a `restore` subcommand that re-applies the saved power profile on boot without notification spam.
- Enhanced `dark-tools-rs/src/bin/theme_manager.rs` and compiled binary `quickshell/theme-manager` with a `restore` subcommand to sync Niri, Mako, Rofi, Fuzzel, and QuickShell themes on boot without overriding custom user wallpapers.
- Added file existence checks before setting theme wallpapers in `theme_manager.rs` to prevent broken commands or overwriting custom wallpapers.
- Integrated `Quickshell.Io.FileView` with `preload: true` and `watchChanges: true` inside `quickshell/components/Theme.qml` for synchronous, instant loading and live reload of `quickshell/theme.json` and `quickshell/bar_style.json`, removing the default race condition and flicker on startup.
- Dynamically bound `activeThemeId` and `activeThemeName` in `quickshell/components/Settings.qml` to `Components.Theme` and added an auto-refresh listener on theme dialog open.
- Updated `quickshell/wallpaper-engine/wallpaperctl` to track engine enabled/disabled state in `~/.config/niri/wallpaper_engine_enabled`, ensuring `init` respects when the engine was toggled off, while seamlessly restoring the saved `config.json` (active wallpaper/canvas color/effects/FPS/quality) when enabled.
- Added `powerprofile.sh restore &` and `theme-manager restore &` hooks to `niri/startup.sh`.
- Updated `.gitignore` to prevent committing runtime state files `niri/power_profile` and `niri/wallpaper_engine_enabled`.
- Updated technical documentation in `docs/complex/QUICKSHELL.md` and `docs/complex/POWER.md`.
