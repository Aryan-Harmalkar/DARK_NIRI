# Session: Fix QuickShell Reload Crash Notifications (Broken Pipe SIGABRT in Rust Tools)

**Date:** 2026-09-16 12:48:00
**Category:** fixes

## Modifications
- **Diagnosed "Service Crash" Notification Root Cause**:
  - Inspected `systemd-coredump` journal logs and coredump traces (`coredumpctl`).
  - Discovered that during QuickShell updates or reloads (`reload-shell.sh`), `killall qs` terminated the parent QuickShell process while background network/hardware query processes (`quickshell/wifi.sh` and `quickshell/bluetooth.sh`) were still running.
  - When writing serialized JSON to standard output, the severed pipe (`EPIPE` / Broken pipe) triggered Rust's `println!()` to panic (`library/std/src/io/stdio.rs:1166:9: failed printing to stdout: Broken pipe (os error 32)`).
  - Because `panic = "abort"` is configured in `Cargo.toml` for release builds, the panic immediately executed `abort()`, triggering a core dump (`SIGABRT`) and prompting the system crash reporting notification.
- **Implemented Broken-Pipe Resilience in `dark-tools-rs`**:
  - Updated `dark-tools-rs/src/common.rs` with `ignore_sigpipe()` (setting `SIGPIPE` to `SIG_IGN`), `safe_println()`, and `safe_print_json()`, which safely writes to `stdout` and discards `BrokenPipe` errors without panicking.
  - Refactored `dark-tools-rs/src/bin/wifi.rs` and `dark-tools-rs/src/bin/bluetooth.rs` to call `common::ignore_sigpipe()` on startup and use `safe_print_json()`.
  - Added `libc = "0.2"` to `dark-tools-rs/Cargo.toml` for safe POSIX signal handling.
  - Recompiled release binaries and deployed them to `quickshell/wifi` and `quickshell/bluetooth`.
- **Hardened `quickshell/reload-shell.sh`**:
  - Added `killall -9 wifi bluetooth 2>/dev/null` prior to restarting `qs` to cleanly terminate any active helper subprocesses.
- **Verified Resilience**:
  - Tested piped commands (`wifi.sh list | head -n 0` and `bluetooth.sh list | head -n 0`) — verified exit code 0 with zero panics or core dumps.
  - Executed repeated QuickShell reloads via `quickshell/reload-shell.sh` — verified 0 core dumps generated in `coredumpctl`.
